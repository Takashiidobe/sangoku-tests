# sangoku-tests

Track Sangoku codegen against the smallest measured reference on SM83. The
README shows Sangoku versus best for each test, with notes for improving it.
Body sizes and complete helper-inclusive costs have separate references.

## Run the suite

Install Python 3.10+, SDCC (`sdcc`, `sdar`, and the SM83 library), and RGBDS
(`rgbasm`, `rgblink`, `rgbfix`). Build Sangoku with `cargo build --release` in
`../sangoku`, or pass `--sangoku PATH`.

Install the LLVM tools, build the pinned native Rust-Z80 compiler, then run:

```bash
python3 tools/setup_llvm_z80.py
python3 tools/setup_rust_z80.py
python3 tools/compare.py
python3 tools/report.py
```

The setup commands support Linux x86_64. The native build needs Git, Clang, LLD,
CMake, Ninja and ccache, and compiles both LLVM and Rust on its first run. Use
`python3 tools/setup_rust_z80.py --jobs 4` to limit parallel build jobs. Both
source commits are pinned; rerunning setup reuses the checkout and build.

Use `--llvm-rustc PATH` for an existing Rust-Z80 compiler with SM83 `core`,
`alloc`, runtime archives and its matching bundled LLD. Use `--llvm-z80 BIN_DIR`
for another LLVM tools installation. Native mode attempts every fixture family
and retains actual compilation failures and link diagnostics. Reports record the
frontend method, tool versions and hashes. A compilation failure makes the
runner exit nonzero after saving all results. Use `--without-llvm-z80` to run
Sangoku and SDCC alone.

For the earlier scalar-only experiment, install
`rustup toolchain install nightly-2026-10-25 --profile minimal` and pass
`--llvm-frontend ir`. This retargets host Rust LLVM IR and excludes pointer,
aggregate, float and wide-integer fixtures. `--llvm-rust-toolchain NAME` selects
its frontend. Native mode does not retarget host IR.

The suite writes `results/comparison.json` and saves assembly and intermediate
IR under `build/`. Sangoku and SDCC artifacts are cached; LLVM-Z80 reruns. Pass
`--no-cache` to rebuild all compiler artifacts.

## Improve one test

Use `--list` to find case IDs. Save a baseline, change and rebuild Sangoku, then
rerun the same tests:

```bash
python3 tools/compare.py --case u16_mul3 --output build/before.json
# change Sangoku, then rebuild it
python3 tools/compare.py --case u16_mul3 --output build/after.json
python3 tools/report.py build/after.json --case u16_mul3 --dependencies
python3 tools/report.py build/after.json --baseline build/before.json
```

The case report shows all three compilers' assembly, the best reference for each
size metric, and Sangoku's byte gap. Add `--mode speed` to inspect the other
optimization mode. Each mode has its own size results and optional cycle
measurements for declared inputs.

The baseline report shows absolute Sangoku changes and the gap to the best
reference. It flags changed references, changed Rust fixtures and lost
measurements. Add `--max-growth 0` to fail on any byte growth or lost result;
set a higher byte allowance if needed. For partial reports, select the same
cases and modes in both runs.

Use `python3 tools/report.py --rust-only` to inspect cases SDCC cannot compile,
including native LLVM failures. The [detailed comparison](results/rust-only.md)
keeps compiler-specific results, coverage and diagnostics for both modes.

## Measure cycles for explicit inputs

Build SameBoy with `make lib` in its checkout. The default shared-library path
is `~/SameBoy/build/lib/libsameboy.so`; override it with
`--sameboy-library PATH`. Run timing subcases with the comparison, then refresh
the README:

```bash
python3 tools/compare.py --case u16_mul3 --cycles --output build/mul3.json
python3 tools/report.py build/mul3.json --case u16_mul3
```

To attach timings to the existing full report and refresh its README subrows:

```bash
python3 tools/measure_cycles.py
python3 tools/update_readme.py
```

Each subrow shows an exact input, expected result, and Sangoku / best T-cycles.
Size and speed builds have separate subrows. All executed helper code and the
return are timed; caller setup and result stores are excluded. Outputs must
match before a timing can become a reference. The runner uses DMG normal speed
with LCD and interrupts disabled. Inputs and expected outputs are declared in
[cycle_cases.py](tools/cycle_cases.py); only those probes are timed.

Baseline reports compare each input separately. Use `--max-cycle-growth 0` with
`--baseline` to reject cycle growth or lost timings; `--max-growth` remains a
separate byte budget. Rebuild the comparison and timings after compiler changes.

You can also time a linked RGBDS assembly snippet directly:

```bash
python3 tools/cycle_runner.py probe.asm --entry mul3 --reg de=7 --expect bc=21
```

## Interpret references

“Best observed” means the smaller available SDCC or LLVM-Z80 result for that
metric; ties preserve both compilers. It is not a proof of optimality. Native
calling conventions differ. Timed subcases check their declared outputs on the
target emulator; other inputs and untimed fixtures have no target validation.

Body sizes exclude external runtime helpers. Complete costs include transitive
runtime dependencies and fixture helpers, when fully measurable. Native LLVM
costs come from isolated linked ELF sections, including constant data and
section padding. SDCC archive-member costs can include other routines, and
dependencies may already be shared in a larger program. Missing helper costs
never count as zero. Standalone Sangoku integer/float runtime totals remain
unavailable, so their complete-cost gaps are not reported.

LLVM machine outlining is disabled to keep per-test measurements independent of
shared fragments extracted from neighboring probes. Sizes can therefore differ
from a normal LLVM build with outlining enabled.

See the [per-case catalog](#per-case-codegen-catalog) for every measurement and
investigation lead. After a full run, refresh the catalog and detailed report
together (requires Prettier):

```bash
python3 tools/update_readme.py
python3 tools/update_readme.py --check
```

`--check` verifies both generated documents without writing. Run harness tests
with `python3 -m unittest discover -s tests`.
